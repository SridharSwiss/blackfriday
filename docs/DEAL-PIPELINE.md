# AKTIONS.CH — how the live-deals feed was researched, verified and published (19 Nov 2026)

Hand-off for another Claude session. Repo `SridharSwiss/blackfriday`, site https://aktions.ch (Vite SPA). Standing rules from the owner: **every code/data change is committed and pushed to `main`** (Vercel auto-deploys; `git pull --rebase origin main` first — scheduled tasks also commit there), and **spend tokens economically without lowering quality or extensibility**. Commit trailers: `Co-Authored-By: Claude …` + `Claude-Session: …` as given by the session.

## 1. The one fact that shapes everything
The cloud container **cannot reach shop sites**: shell `curl`, container Playwright and most `WebFetch` URLs are refused by the egress proxy (`ERR_TUNNEL_CONNECTION_FAILED`). Only `WebSearch`/`WebFetch` (allow-listed, shared ~200-search budget per turn) work from the container. **The user's real Chrome does reach every shop** → drive it with the `claude-in-chrome` MCP tools. It needs the Claude desktop/Chrome extension connected (`list_connected_browsers`) and the user must approve its permission prompts (agents sit "waiting for permission" until they do; ask for "always allow").

## 2. Data model (src/data/live-ch.js → `LIVE_CH`)
Row: `{shop, cat, name, spec, price, was, cur, checked, until?, type, url, src[], note?, percent?}`. Rules: exact product URL, real struck price, ≥10 % off, CHF (EUR for amazon.de), live today. Row is shown until `until`, else 3 days after `checked`. `shop` must exist in `src/config/shops.js` (`SHOPS` key → name + `search()`), else rendering breaks. `src/config/affiliates.js` `affLink()` tags outbound links (Amazon.de tag `blackfrida08d-21`, Amazon.com `blackfrid0c4a-20`; any amazon.de/.com URL is tagged regardless of shop key). Amazon URLs are also tagged in the data file.

## 3. Pipeline (what actually worked)
**Phase A — discovery by search agents (WebSearch).** 12 research agents (one per shop group/category) wrote JSONL candidates under a strict BRIEF; `collect.mjs` validated/deduped → 1,009 candidates. Then a first verification attempt with 18 Opus agents **died on the 5-hour usage limit (HTTP 429)** — use **Sonnet** agents for bulk work and verify at *listing-page* level, not per product via WebSearch. Result: 944 rows after dropping ~99.

**Phase B — re-verification in real Chrome (the efficient method).** Build one input JSON per shop (`[{id,shop,name,price,was,url}]`, `id` = index in `LIVE_CH`), launch one Sonnet agent per shop group, each with its **own tab** (shared Chrome; never touch others' tabs; close yours). Method in `scripts/deals/BROWSER.md`:
1. Navigate the tab to the shop domain, inspect ONE product page to learn where price/struck price live (JSON-LD `Product.offers.price`, `meta`, DOM).
2. Run ONE `javascript_tool` call that `fetch(url,{credentials:'include'})`s ≤60 same-origin URLs (concurrency 4–6, 150–300 ms gaps), parses with `DOMParser`/regex and returns a **compact** array — never raw HTML.
3. Output JSONL `{"id":N,"v":"ok|updated|no_deal|broken|soldout|blocked","price_now":…,"was_now":…}`.
Per-shop facts learned: Fust → fetch `/p/<code>` only (slug optional); Galaxus/Digitec → JSON-LD price OK, "struck" = standard-price meta (may be list price); Brack → JSON-LD has several prices, check both numbers appear in page text; Manor marketplace rows need the rendered page; Pfister member prices not marked on page; **Amazon.de in a Swiss Chrome shows CHF** (agent converted at an inferred rate → untrusted; set page to EUR or keep old rows); **Zalando returns 429/"Kleiderpanne" after ~10 pages, Decathlon/Salt rate-limit, Interdiscount bot-wall even in Chrome** → slow pacing or mark `blocked`; JSON-LD `OutOfStock` is unreliable (Zalando). Tool output is capped (~1,000 chars/call): **listing-page extraction by agents is inefficient** (an agent got only 7 rows from Decathlon) — put the parsing inside the page JS and return compact tuples.

**Phase C — apply (`scripts/deals/apply.mjs`).** Idempotent: always re-reads a frozen base (`live-ch.base.js`), applies verdicts from `out/*.jsonl`, merges `new/*.json`, tags Amazon URLs, writes `live-ch.js`. Semantics: `ok`→keep + `checked` today; `updated`→new price/was (require was>price and ≥10 % off; Amazon "updated" rows are kept unchanged); `no_deal|broken|soldout`→drop; `blocked`/no verdict→keep as is. Setup: `mkdir -p .deals-work/{in,out,new}; cp src/data/live-ch.js .deals-work/live-ch.base.js; DEALS_WORK=.deals-work node scripts/deals/apply.mjs`. (Gotcha hit: base file has `];` followed directly by the next `export`; slice with `j`, not `j+1`.)

**Phase D — new rows without per-item verification (owner-approved) + spot check.** Clean candidates (https URL, price>0, was>price, ≥10 % off, known category list, not expired, dedupe by URL), add `checked`, `src`, and a note ("price from the shop's sale listing … confirm at the shop"), write to `new/*.json`. **Spot-check a random sample per shop in Chrome** (this run: 8 Galaxus, 5 Brack, 3 Fust → 16/16 matched; Interdiscount/Decathlon not checkable).

**Phase E — publish.** `npm run build` → `pkill -f "vite preview"; nohup npx vite preview --port 4174 &` → Playwright smoke test (cards render, tab counter, no `pageerror`, no horizontal scroll at 1440×900 and 390×844) → commit → `git pull --rebase origin main` → `git push origin HEAD:main`. Ship in **waves** (after each batch of verified shops) so partial progress is always deployed.

Everything lives on one **Live deals** page (Top-100 tracker, undiscounted catalogue, price-less US lines no longer listed; old `#top/#categories/#best/#us` map to Live with presets via `LEGACY` in `main.js`). Fit-to-viewport layout logic is in `fit()`; don't add elements to the card top row without re-checking card height.
